# CPU
**CPU**(Central Processing Unit, 중앙제어장치)

최초로 대량 생산된 CPU는 Intalel 4004로, 이탈리아 물리학자이자 공학자 Federico Faggin가 60년대 후반 설계하였다. 4비트 아키텍처로, 오늘날 사용되는 64비트 아키텍처 프로세서보다 훨씬 덜 복잡하다.

CPU는 이진 데이터를 읽고, 그에 따라 연산을 수행한다. 이 이진 데이터는 연산코드와 이를 따르는 데이터로 이루어진다. 이것을 거의 일대일 수준으로 번역한 것이 어셈블리이다.

# 명령 포인터
**램**에는 실행되고 있는 프로그램들의 모든 데이터가 저장된다. CPU는 항상 램에서 코드를 읽어온다. 

CPU는 항상 다음 코드를 램의 어느 위치를 불러올 지를 나타내는 Instruction pointer(포인터?)를 저장한다. 코드가 실행된 뒤 포인터는 RAM의 바로 다음으로 이동하며 *실행-포인터 지정*이 반복되며 코드가 순차적으로 실행되는 것이다. 일부 코드는 무조건적, 또는 조건적으로 포인터가 바로 다음 위치로 이동하지 않고 정해진 위치로 이동하게 한다. 이것이 반복문과 조건문을 가능하게 한다.

포인터는 **레지스터**에 저장된다. 레지스터는 CPU에 있는 작고 아주 빠른 저장 공간이다.

# 권한
**커널**: OS(Operating System, 운영체제)의 핵심으로, 컴퓨터가 부팅될 때 포인터가 시작되는 프로그램이 커널이다. 메모리, 장치 등에 대한 거의 모든 접근 권한을 가진다.

모드에 따라 프로세서의 권한이 달라진다. 현대에는 보통 커널 모드와 사용자 모드로 나뉜다.
커널 모드에서 CPU는 모든 명령을 실행하고 아무 메모리에 접근할 수 있다. 사용자 모드에서는 일부 명령만 허용되며, 입/출력, 메모리에 대한 접근에 제한이 있다. 보통 커널과 드라이버는 커널 모드에서, 앱은 사용자 모드에서 실행된다. 

x86-64 아키텍처에서 *현재의 모드가 무엇인지(CPL, Curent privilege level, 현재 권한 레벨)*는 cs(Code Segment)라 불리는 레지스터의 최하위 비트 두 개에서 읽어온다. 2비트이므로 4가지 상태를 나타낼 수 있다. 0이 커널, 3이 사용자 모드이며, 1과 2는 드라이버 실행에 쓰인다.

사용자 모드에서 실행되는 프로그램이라도 OS와 상호작용하고, 메모리에 접근해야 할 때가 있다. 이때 쓰이는 것이 시스템콜이며, 시스템콜은 프로그램이 사용자 공간에서 커널 공간으로 전환하고 프로그램 코드에서 OS 코드로 점프할 수 있게 하는 절차이다.

이 전환은 프로세서의 **소프트웨어 인터럽트**라는 기능을 통해 이루어진다.

부팅 과정에서 OS는 **인터럽트 벡터 테이블**(Interrupt Vector(Descriptor) Table)을 램에 저장하고 CPU에 등록한다. IVT는 인터럽트 넘버를 핸들러 코드 포인터에 매핑한다. 프로그램은 INT와 같은 명령어를 통해 IVT에서 주어진 인터럽트 넘버를 찾고 커널 모드로 전환한 다음 명령 포인터를 IVT에 저장된 메모리 위치(핸들러 코드 포인터)로 점프시킨다.

인터럽트가 끝나면 IRET과 같은 명령을 사용해 다시 사용자 모드로 전환하고 명령 포인터를 인터럽트가 트리거된 곳으로 돌려놓는다.


> 진짜 어렵네


다시 최대한 쉽게 써보면 IVT에서 각 인터럽트 넘버는 특정 위치를 가리키고 있고, 시스템 인터럽트가 일어나면 커널 모드로 주어진 인터럽트 넘버가 가리키는 위치로 이동해서 OS 코드를 실행한다. 그 뒤 다시 사용자 모드로 전환하고 원래 위치로 돌아간다.

# 멀티태스킹
여러 프로세스가 번갈아 실행되게 함으로써 여러 프로세스를 동시에 실행할 수 있다.
OS 스케줄러는 타이머 칩으로 하드웨어 인터럽트를 트리거한다.

OS는 프로그램 코드 실행 전에 타이머 칩이 일정 시간 뒤 인터럽트를 트리거하도록 설정한다. OS는 사용자 모드로 전환해 프로그램 코드를 실행한다. 시간이 다 되면 커널 모드로 전환하고 OS 코드로 돌아오도록 하는 하드웨어 인터럽트가 트리거된다. 이렇게 되면 OS는 프로그램이 중단된 위치를 저장한다. 이를 여러 프로그램에 걸쳐 반복하면 멀티태스킹이 가능하다. 이는 프리엠티브 멀티태스킹이라고 부르며, 프로세스가 인터럽트되는 것을 프리엠셔닝라고 부른다.

## 타임슬라이스
타임슬라이스는 OS 스케줄러가 정하는 시간 길이이다. 프로세스는 타임슬라이스동안 실행된 뒤 프리엠션된다. 모든 프로세스에 같은 타임슬라이스를 적용하는 것을 고정 타임슬라이스 라운드-로빈 스케줄링이라고 한다. (라운드-로빈 스케줄링은 프로세스 간의 우선순위가 없다)

고정 타임슬라이스 스케줄링 말고도 타겟 레이턴시를 지정하는 방법이 있다. 타겟 레이턴시는 프로세스가 프리엠션 된 뒤 다시 실행되기까지의 시간이다. 
예를 들어 타겟 레이턴시가 20ms이고 프로세스가 5개라면 타임슬라이스는 20/5=4ms가 되며, 각 프로세스는 20ms마다 실행되게 된다. 프로세스가 많아지면 타임슬라이스가 너무 짧아질 수 있다. 프로세스의 중단 위치를 저장하고 불러오는 것은 컴퓨팅 리소스를 소모하기 때문에 타임슬라이스를 너무 짧게 지정하는 것은 퍼포먼스 문제를 일으킬 수 있다. 그래서 보통 타임슬라이스 최소 한도가 있어서 프로세스가 충분히 많아지면 타겟 레이턴시가 늘어난다.

오늘날의 컴퓨터는 가변 타임슬라이스 라운드-로빈 스케줄링과 비슷하지만 보통 프로세스 우선순위를 고려한다.

초기 Mac OS와 같은 과거 OS는 코오퍼레이티브 멀티태스킹을 사용했다. 코오퍼레이티브 멀티태스킹에서는 OS가 타임슬라이스를 정하는 대신 프로그램이 소프트웨어 인터럽트를 통해 자발적으로 프로세스를 OS로 넘기고, OS가 다음으로 스케줄링된 프로세스를 실행할 수 있게 한다. 시간적 일관성을 유지하는 것이 거의 불가능하고, 멀웨어나 잘못 설계된 프로그램이 OS를 멈추게 할 수 있기 때문에 이제는 사용되지 않는다.
